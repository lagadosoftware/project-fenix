---

# Purpose

This document defines the documentation and repository standards used throughout Project Fenix.

Its purpose is to ensure consistency, readability, maintainability, and professional engineering practices across the entire project.

---

# Scope

These standards apply to every folder, document, diagram, script, and future module contained within the Project Fenix repository.

---

# Guiding Principles

Project Fenix follows these principles:

- Documentation before implementation whenever practical.
- Consistency is preferred over personal preference.
- Every major decision should be documented.
- Documentation evolves together with the project.
- Simplicity is preferred over unnecessary complexity.

# Project Standards

## PF-STD-001
### Every major folder shall contain a README.md

Each project folder must contain a README.md file explaining:

- Purpose
- Contents
- Status
- Related documents

---

## PF-STD-002
### Documentation shall use semantic versioning.

Example:

- v0.1.0
- v0.2.0
- v1.0.0

---

## PF-STD-003
### Every formal project document shall include:

- Title
- Document ID (if applicable)
- Version
- Status
- Author
- Purpose
- Related Documents
- Revision History

---

## PF-STD-004
### Commit messages shall be meaningful.

Examples:

- Initialize project structure
- Add Company documentation
- Update Production Process
- Create SQL database schema

Avoid messages like:

- Update
- Changes
- Test
- Stuff

---

## PF-STD-005
### Documentation shall be written in English.

English is the official documentation language of Project Fenix.

---

## PF-STD-006

### Project documentation shall be maintained within the Git repository.

All project documentation shall be stored inside the Project Fenix repository whenever practical, ensuring that documentation evolves together with the project.
